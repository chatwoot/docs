This document helps you to configure Cloudfront as the asset host for Chatwoot. If you have a high traffic website, we would recommend setting up a CDN for Chatwoot.

<Note>
This guide covers the CloudFront distribution setup. For the asset-upload workflow (extracting `public/` from the Chatwoot image, uploading to S3, configuring `ASSET_CDN_HOST` at runtime) and CDN-agnostic notes that apply to any provider, see the [Asset CDN Setup guide](/self-hosted/deployment/performance/asset-cdn-setup).
</Note>

## Configure a Cloudfront distribution

**Step 1**: Create a Cloudfront distribution.

![create-distribution](/self-hosted/images/cloudfront/create-distribution.png)

<Note>
CloudFront used to offer separate "Web" and "RTMP" distribution types. [RTMP distributions were retired on 2020-12-31](https://repost.aws/questions/QUoUZgHZh7SEWlnQUPlBmVNQ), so the modern create-distribution wizard no longer asks you to pick a delivery method — just create the distribution and continue with the steps below.
</Note>

**Step 2**: Configure the Origin Settings as the following.

![origin-settings](/self-hosted/images/cloudfront/origin-settings.png)

- Provide your Chatwoot Installation URL under Origin Domain Name.
- Select "Origin Protocol Policy" as Match Viewer.

**Step 3**: Configure Cache behaviour.

![cache-behaviour](/self-hosted/images/cloudfront/cache-behaviour.png)

- Configure **Allowed HTTP methods** to use *GET, HEAD, OPTIONS*.
- Configure **Cache and origin request settings** to use *Use legacy cache settings*.
- Select **Whitelist** for *Cache Based on Selected Request Headers*.
- Add the following headers to the **Whitelist Headers**.
![extra-headers](/self-hosted/images/cloudfront/extra-headers.png)
  - **Access-Control-Request-Headers**
  - **Access-Control-Request-Method**
  - **Origin**
- Set the **Response headers policy** to **CORS-With-Preflight**

**Step 4**: Click on **Create Distribution**. You will be able to see the distribution as shown below. Use the **Domain name** listed in the details as the **ASSET_CDN_HOST** in Chatwoot.

![cdn-distribution-settings](/self-hosted/images/cloudfront/cdn-distribution-settings.png)

## Add ASSET_CDN_HOST in Chatwoot

Your CloudFront distribution exposes a domain in the format `<distribution>.cloudfront.net`. Set `ASSET_CDN_HOST` to the **full URL including the `https://` scheme**:

```bash
ASSET_CDN_HOST=https://<distribution>.cloudfront.net
```

<Note>
A scheme (`https://` or `http://`) is required. Chatwoot's runtime injects `ASSET_CDN_HOST` verbatim into `window.__VITE_BASE__` and into the widget SDK snippet, so a bare host like `d123.cloudfront.net` produces URLs like `d123.cloudfront.net/vite/chunk.js` — browsers treat those as relative paths and fail to load the chunks. Use the same scheme your Chatwoot app is served on (HTTPS for production).
</Note>

## Benefits of Using CDN

<Tip>
Using a CDN provides several benefits for your Chatwoot installation:
</Tip>

1. **Faster Asset Loading**: Assets are served from edge locations closer to users
2. **Reduced Server Load**: Static assets are served from CDN, reducing load on your application server
3. **Better User Experience**: Faster page load times improve user experience
4. **Global Availability**: Assets are cached globally for users worldwide
5. **Bandwidth Savings**: Reduces bandwidth usage on your origin server

## Troubleshooting

### CORS Issues

If you encounter CORS issues after setting up CloudFront:

- If CloudFront's origin is your Chatwoot Rails server (pull-CDN mode), Rails already emits `Access-Control-Allow-Origin: *` for asset paths (`/vite/*`, `/packs/*`, `/audio/*`, `/assets/*`, `/brand-assets/*`, `/dashboard/*`, `/integrations/*`). Confirm CloudFront is forwarding the `Origin` request header (Step 4 above) and not stripping the response header in your cache policy. See the [CORS section in the Asset CDN Setup guide](/self-hosted/deployment/performance/asset-cdn-setup#cors) for the full breakdown of pull-CDN vs. object-storage CDN scenarios.
- If CloudFront's origin is an S3 bucket (object-storage mode), Rails is not in the request path — set the CORS allowlist on the S3 bucket directly via bucket → Permissions → Cross-origin resource sharing.

`CORS_ORIGINS` is a separate setting that controls API CORS for `/api/*`, not asset CORS. You generally don't need to set it for asset delivery.

### Cache Invalidation

To invalidate CloudFront cache after updating assets:

1. Go to CloudFront console
2. Select your distribution
3. Create an invalidation for `/*` to clear all cached assets

### SSL Certificate

For custom domain names with CloudFront:

1. Request an SSL certificate in AWS Certificate Manager (ACM)
2. Configure the certificate in your CloudFront distribution
3. Update your DNS to point to the CloudFront distribution

<Note>
SSL certificates for CloudFront must be requested in the US East (N. Virginia) region regardless of where your distribution is located.
</Note>
